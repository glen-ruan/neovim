# Neovim 嵌入式开发流程

本文记录 IAR 和 Keil 工程在 Neovim 中的语言服务、编译和烧录流程。日常编辑操作见 [快捷键说明](Neovim快捷键说明.md)。

## 1. 语言服务原理

首次安装配置后，Mason 会自动安装 `clangd`。可以用下面的命令确认：

```vim
:LspAvailability
```

如果 `clangd` 显示为 `missing`，执行：

```vim
:MasonInstall clangd
```

`clangd` 可执行文件和 `compile_commands.json` 缺一不可：前者提供语言服务，后者告诉 clangd 当前工程实际使用的 CPU、宏和包含路径。

clangd 不会读取 IAR `.ewp` 或 Keil `.uvprojx`。它需要标准文件：

```text
IAR/Keil 工程配置
        ↓
生成 compile_commands.json
        ↓
clangd 读取每个源文件的 CPU、宏和包含路径
        ↓
Neovim 获得补全、跳转、引用和诊断
```

`compile_commands.json` 是机器生成文件。工程增加文件、修改宏、修改包含路径、切换 Target/Configuration 后，要重新生成。

## 2. IAR 工程语言服务

IAR 功能仅在装有 IAR Embedded Workbench 的 Windows 机器上启用。在包含单个 `.ewp` 的工程根目录启动 Neovim：

```text
cd <IAR 工程根目录>
nvim .
```

执行：

```vim
:IarClangd
```

工程有多个 Configuration 时指定名称：

```vim
:IarClangd Debug
```

生成器调用 IAR 官方构建输出，取得每个源文件的真实宏和包含目录，再转换为 clangd 参数。

目录中有多个 `.ewp` 时，在 PowerShell 明确指定：

```powershell
& "$env:LOCALAPPDATA\nvim\tools\iar-clangd.ps1" `
  -Project ".\Project\CPU\EWARM\Project.ewp" `
  -Configuration "FWLib" `
  -OutputDirectory (Get-Location)
```

`:IarClangd` 会把 `compile_commands.json` 写入启动 Neovim 时的工作目录。应先在工程根目录执行 `nvim .`；数据库必须与 `source`、`Libraries` 等源码目录处于共同的上级目录，clangd 才能为全部源文件找到它。

## 3. Keil MDK5 工程语言服务

在 Keil SDK 或工程根目录启动：

```text
cd <Keil 工程或 SDK 根目录>
nvim .
```

执行：

```vim
:KeilClangd
```

操作顺序：

1. 从列表选择一个 `.uvprojx` 工程。
2. 如果该工程有多个 Target，再选择 Target。
3. 工具调用 µVision 官方 `-et` 导出目标配置。
4. 临时 `.cprj` 被解析后恢复或删除。
5. 在当前 Neovim 工作目录生成 `compile_commands.json`。
6. clangd 自动重启。

一个工作目录一次激活一个工程 Target 的编译配置。切换工程或 Target 后再次执行 `:KeilClangd`，共享源文件的宏和包含目录会跟随最后选择的目标。

命令行方式：

```powershell
& "$env:LOCALAPPDATA\nvim\tools\keil-clangd.ps1" `
  -Project ".\path\to\Project.uvprojx" `
  -Target "Target Name" `
  -OutputDirectory (Get-Location)
```

若 Keil 或 IAR 安装在其他位置，可以设置用户环境变量：

```powershell
[Environment]::SetEnvironmentVariable("UV4_EXE", "<UV4.exe 的完整路径>", "User")
[Environment]::SetEnvironmentVariable("IARBUILD", "<IarBuild.exe 的完整路径>", "User")
```

## 4. 在 Neovim 中编译与烧录

从工程根目录执行 `nvim .` 后，按 `空格 f t` 打开浮动 PowerShell。再次按 `空格 f t` 会隐藏终端，正在运行的任务会继续。也可以用 `:terminal` 打开普通终端 Buffer；简单的一次性命令可以写成 `:!命令`。

先用 `Get-Location` 确认终端位于工程根目录。Keil 增量编译命令是：

```powershell
& $env:UV4_EXE -j0 -b ".\path\to\Project.uvprojx" -t "Target Name" -o ".\keil-build.log"
Get-Content ".\keil-build.log"
```

其他常用 Keil 命令：

```powershell
# 重新翻译并链接当前 Target
& $env:UV4_EXE -j0 -r ".\path\to\Project.uvprojx" -t "Target Name" -o ".\keil-rebuild.log"

# 清理所有 Target
& $env:UV4_EXE -j0 -c ".\path\to\Project.uvprojx"

# 清理后重新翻译当前 Target
& $env:UV4_EXE -j0 -cr ".\path\to\Project.uvprojx" -t "Target Name" -o ".\keil-clean-rebuild.log"
```

连接调试器和目标板后烧录：

```powershell
& $env:UV4_EXE -j0 -f ".\path\to\Project.uvprojx" -t "Target Name" -o ".\keil-flash.log"
Get-Content ".\keil-flash.log"
```

`-f` 使用 `.uvprojx` 中 **Options for Target → Utilities** 已保存的调试器、Flash Algorithm 和下载设置。第一次命令行烧录前，应先在 µVision 中成功完成一次手动 Flash Download。µVision 构建退出码为：`0` 无错误和警告、`1` 只有警告、`2` 编译错误、`3` 严重错误。

IAR 工程在浮动终端中编译：

```powershell
# 增量构建 Debug Configuration
& $env:IARBUILD ".\path\to\Project.ewp" -make "Debug" -log all

# 完整重新构建 Debug Configuration
& $env:IARBUILD ".\path\to\Project.ewp" -build "Debug" -log all

# 清理 Debug Configuration
& $env:IARBUILD ".\path\to\Project.ewp" -clean "Debug" -log all
```

`IarBuild.exe` 只负责构建。IAR 烧录需要按工程配置 C-SPY 命令行流程，或者调用芯片厂商提供的烧录工具；具体命令取决于调试器、芯片和 `.ddf`/`.mac` 配置，不能只由 `.ewp` 推导出一条通用烧录命令。

## 5. CMake LSP 与 Python 3.14

`cmake-language-server` 0.1.11 要求 Python `>=3.8,<3.14`。当系统 Python 是 3.14 时，Mason 无法安装它，因此发行版不会把它加入 Mason 自动安装列表。clangd 和其他 LSP 不受影响。

推荐用 `uv` 管理独立的 Python 3.13，仅供这个工具使用；系统 Python 保持不变。安装脚本同时固定 `pygls 1.3.1`，避免 `cmake-language-server 0.1.11` 与 `pygls 2.x` 的接口不兼容：

```bash
~/.config/nvim/scripts/install-cmake-lsp.sh
```

Windows：

```powershell
& "$env:LOCALAPPDATA\nvim\scripts\install-cmake-lsp.ps1"
```

安装完成后重新启动 Neovim，并执行 `:LspAvailability` 检查 `cmake`。
